# Карта проекта

> Last reviewed: 2026-10-21

Срез состояния. Обновляется после каждого мержа (навык `merge-pr`).

## Цель

B2B-кабинет: клиент с телефона видит остатки и свою цену, собирает заявку и узнаёт дату машины.

## Где мы

Кабинет написан целиком и покрыт тестами на моке 1С (этапы 0–5 плана); **в браузере его целиком
ещё не проходили** — это первый шаг ниже. Решение владельца 2026-10-20: у 1С будет только
стандартный OData, без HTTP-сервиса, — поэтому ЛК сам читает 1С по OData и сам пишет в неё заказы
(`ONEC_MODE=odata`, `docs/onec-odata.md`). На боевом сервере пока мок: по OData стендом проверены
только каталог и цены.

## Дальше

1. Выкатить `main` (`make prod-redeploy`, `make health`) и пройти кабинет по
   `docs/CHROME_CHECK_PROMPT.md` — это регресс на моке и первая живая проверка интерфейса.
2. Владелец с программистом 1С: сменить пароль `odata.user` (он звучал в чате), сузить публикацию
   (убрать зарплату и персональные данные), права — чтение нужных объектов и запись только
   `Document_ЗаказКлиента`; вернуть в публикацию `Document_ЗаданиеНаПеревозку` и
   `Document_РеализацияТоваровУслуг`, опубликовать `InformationRegister_АналитикаУчетаПоПартнерам`.
3. Стенд, режим «OData 1С — клиенты и соглашения»: прислать отчёт — по нему уточнить
   сопоставление полей и решить #46 (выбор соглашения в корзине). **До #46 заказы по OData не
   включать**: у клиента с несколькими соглашениями заказ ушёл бы по самому позднему.
4. Замер на тестовой базе до любого включения: длительность прогонов каталога, цен, остатков и
   клиентов (журнал запросов стенда), пик памяти контейнера (лимит 512 МБ; цены уже падали по
   памяти — #57). Не уложились — поднять лимит или реже опрашивать.
5. Включать потоки по одному, каждый — после проверки: `ONEC_MODE=odata` (каталог, цены, остатки)
   → `ONEC_ODATA_CLIENTS` (сначала с тестовым порталом) → `ONEC_ODATA_ORDERS` (тестовый заказ,
   затем один настоящий на тестовой базе, сверка с заказом, созданным в 1С руками) →
   `ONEC_ODATA_TRIPS` (после публикации документа). Откат — вернуть флаг или `ONEC_MOCK=true`:
   записанные в 1С заказы флаг не отменяет — их находят по `НомерПоДаннымКлиента` `ЛК-…` и
   помечают на удаление в 1С (`docs/onec-odata.md`, «Откат»).
6. График доставки — решение владельца по #45.

## Что мешает

- Рейсы и «отгружен» — документы выпали из публикации OData.
- График доставки ведётся в Excel (#45).
- Тестовая коробка не поднята: локальное приложение проверяется на боевой коробке.
- Пароль OData прозвучал в чате, в публикации есть зарплата и персональные данные — шаг 2
  «Дальше», до боевого.
- В журнале запросов стенда и логах — только метки наборов и счётчики, без значений; отчёт стенда
  «клиенты» маскирует ФИО и УНП.
