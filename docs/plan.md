## Этап 4. Заявки и доставка — 1 неделя

- [x] Корзина в браузере (только GUID и количество), пересчёт на сервере: цены договора, кратность, остатки, итог; адрес из 1С; комментарий.
- [x] Ближайший рейс по расписанию «Рейсов» (docs/spec.md §8: город, дни недели, отсечка за N дней до рейса, окно прибытия, исключения; время по Минску; разбор — `shared/delivery.ts`), кэш 10 минут; нет рейса или «Рейсы» недоступны — дату согласует менеджер, заявка не блокируется.
- [x] Лимиты на контакт: заявки 10 в час, пересчёт корзины 60 в минуту, звонок раз в 10 минут (и 5 в час на компанию).
- [x] Отправка заявки → сделка в «Заявки ЛК» + товары; идемпотентно по `requestId` (`ORIGIN_ID` сделки + своя таблица, захват отправки против двойного клика); сделка собирается из сохранённой строки; без цены договора и с двумя валютами не уходит.
- [x] Подтверждение → `onec_create_order` (идемпотентно по `externalId` = ID сделки). Подтверждена — сделка вышла из первой рабочей стадии воронки в другую рабочую (стадии и семантика — из `crm.status.list`); проиграна или удалена — заявка отменена; дата доставки — на момент подтверждения; сделки проверяются по кругу, до 50 за запуск. Подтверждение ловим опросом стадии сделки по расписанию, а не `event.bind`: событию нужен контекст установленного приложения (`docs/REST_METHODS.md`, «Что вебхуком не делается»). Та же задача досылает заявки, застрявшие без сделки после сбоя CRM.
- [x] `onec_order_status` → «Мои заявки» с датой отгрузки (только вперёд по жизненному циклу, по GUID заказа); в сделку — отдельным шагом с повтором после сбоя CRM: комментарий, «доставлена»/«отменена» — стадия успеха/провала. Задача `sync:orders` раз в 2 минуты и `sync_orders` в `/mcp/admin`.
- [x] «Позвонить» / «Заказать звонок» — дело ответственному, не чаще раза в 10 минут.
- [x] «Мои заявки» — из базы ЛК по компании сессии.
