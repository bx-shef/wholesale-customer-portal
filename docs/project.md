# Описание проекта

> Last reviewed: 2026-10-12

Полная версия с таблицами и схемой — [документ «Личный кабинет клиента — описание проекта»](https://claude.ai/code/artifact/87b5b41e-6607-4ae5-b7f6-80c1dd969a61). Здесь — выжимка для репозитория.

## Цель

B2B-кабинет для клиентов поставщика: с телефона клиент видит остатки и свою цену, собирает заявку и узнаёт, когда приедет машина. У поставщика Битрикс24 коробка на VM, 1С и телефония. Новые компании заводятся в 1С.

## Функциональность прототипа

- Вход: телефон/email + ключ доступа, который менеджер выдаёт контакту на вкладке «Личный кабинет» в карточке компании.
- Каталог: поиск, фильтры (раздел, бренд, наличие, цена, склад, свойства), сортировка, карточка товара, цена по договору, остатки.
- Корзина и заявка → сделка в воронке «Заявки ЛК», статусы, дата ближайшего рейса в город клиента.
- ИИ-помощник на DeepSeek: поиск, разбор товара, аналоги — только через инструменты ЛК.
- Профиль: договор, менеджер, «Позвонить» / «Заказать звонок».

## Архитектура

- Nuxt 4 + Nuxt Content на основе [bx-shef/skills-site](https://github.com/bx-shef/skills-site). Весь интерфейс — Bitrix24 UI (`@bitrix24/b24ui-nuxt`), Nuxt UI не используется.
- `@bitrix24/b24jssdk`: `B24Frame` во вкладке компании, `B24Hook` на сервере.
- Сервер Nitro — единственная точка доступа к Б24, 1С и DeepSeek; браузер к ним напрямую не ходит.
- MCP на [@nuxtjs/mcp-toolkit](https://github.com/nuxt-modules/mcp-toolkit): `/mcp/client` — инструменты покупателя и ИИ, `/mcp/admin` — обмены `onec_*` и `b24_*`, выдача ключей.
- Два независимых обмена: приложение ↔ 1С и приложение ↔ Битрикс24. Как 1С и Б24 обмениваются между собой, проект не касается.
- Хранение доступа — смарт-процесс «Доступ в ЛК» (хэш ключа), расписание — смарт-процесс «Рейсы».
- Docker: стенд — GHCR + Watchtower за nginx-proxy, бой — ВМ Битрикс24 клиента (nginx bitrix-env → `127.0.0.1`, cron-опрос git с откатом) по схеме [client-bank-alfa-by](https://github.com/bx-shef/client-bank-alfa-by); подробно — [DEPLOY.md](DEPLOY.md).

## 1С в прототипе — моки

Приложение ходит по HTTP в мок-сервер `server/routes/mock-1c/*` (`ONEC_MOCK=true`) с тем же контрактом, что реализует программист 1С. Контракт — [`docs/onec-contract.md`](onec-contract.md), позже `contracts/onec.openapi.yaml` + контрактные тесты. Переключение на реальную 1С — `ONEC_URL`, `ONEC_TOKEN`, без изменения кода.

## План работ

| Этап | Срок | Результат | Параллельно в 1С |
| --- | --- | --- | --- |
| 0. Подготовка | 2–3 дня | Каркас на Bitrix24 UI, CI, Docker; в Б24 — вебхук, поля, смарт-процессы, воронка | — |
| 1. Контракт и мок 1С | 3–4 дня | OpenAPI, мок, контрактные тесты, `onec_*` | Изучение контракта |
| 2. Битрикс24 и доступ | 1 нед. | Вкладка компании, ключи, вход | `GET /clients`, `/contract` |
| 3. Каталог | 1 нед. | Мобильный каталог с ценой клиента | `/catalog`, `/prices`, `/stock` |
| 4. Заявки и доставка | 1 нед. | «Заявка → машина приедет» целиком | `/order`, `/orders/status` |
| 5. ИИ-помощник | 1 нед. | Подбор и аналоги в чате | Сдача сервиса |
| 6. Подключение 1С | 2–3 дня | ЛК на реальной 1С | Исправления по тестам |
| 7. Пилот | 1–2 нед. | Решение о запуске | Поддержка |

Около 6–7 недель на одного разработчика ЛК; демо на моках — после этапа 4.
