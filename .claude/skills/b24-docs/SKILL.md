# Документация Битрикс24: где смотреть и на что не наступать

> Last reviewed: 2026-10-11

Правило — `docs/AGENT_RULES.md` §1: API не вспоминают, его читают. Навык перенесён из
`bx-shef/invoice-from-tasks`; оставлены расхождения, которые касаются и этого проекта.

## Где смотреть

| Что | Как |
|---|---|
| REST: метод, параметры, ответ, ошибки | MCP `b24-dev-mcp`: `bitrix-search` (запрос по-русски или по-английски) → `bitrix-method-details` с точным именем; `field: params` / `returns` / `errors` / `examples`, чтобы не тянуть всё |
| События | `bitrix-search` с `doc_type: ["event"]` → `bitrix-event-details` |
| Встройки, права, установка | `bitrix-search` с `doc_type: ["other", "app_development_docs"]` → `bitrix-article-details` / `bitrix-app-development-doc-details` |
| `@bitrix24/b24jssdk` | `https://bitrix24.github.io/b24jssdk/llms.txt` → нужная страница |
| `@bitrix24/b24ui` | `https://bitrix24.github.io/b24ui/llms.txt` → страница компонента |
| Что реально в установленной версии SDK | типы пакета в `node_modules/@bitrix24/b24jssdk/dist/` |
| Что уже проверено и какие грабли | `docs/REST_METHODS.md` |

## Известные расхождения — проверять в первую очередь

- **MCP смешивает REST v2 и v3.** Метод через v2 (`/rest/`) получает v2-форму: фильтр
  **объектом**; форма v3 отвергается.
- **`bitrix-article-details` подбирает статью по похожему названию**, а не по точному — сверяйте
  заголовок ответа.
- **Непонятый фильтр не отвергается, а игнорируется** — список отдаёт всё. Результат фильтра
  перепроверять своим кодом.
- **Числа приходят строками**, регистр ключей зависит от метода (`crm.item.*` — camelCase,
  классические `crm.*` — UPPER_CASE).
- **Пакет с ошибкой команды** SDK помечает неуспешным целиком.
- **b24jssdk сам повторяет запросы** при сетевой ошибке, таймауте и 5xx. Для записи, которую нельзя
  повторять (`*.add`), это дубли — повторы для таких вызовов выключать, результат сверять чтением.
- **`app.option.set`** — только администратор. Ключи доступа ЛК в опциях не храним — смарт-процесс
  «Доступ в ЛК» (`docs/spec.md`).
- **Коробка, а не облако**: адреса событий и обработчиков встройки должны быть доступны с ВМ
  портала; вебхук коробки — внутренний адрес (`docs/DEPLOY.md`).

## Как записать результат

- Новый метод в коде — строка в `docs/REST_METHODS.md` (иначе краснеет `tests/repoGuards.test.ts`).
- Документация и портал разошлись — записать там же, что замерено, как и когда; статус 📄 → ✅
  только после живой проверки.
- В описании PR — какие страницы документации прочитаны.
- Документация молчит — так и написать: «не нашёл в документации», и что сделано взамен.
