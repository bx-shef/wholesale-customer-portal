# Ревью PR: уровень по путям, `/code-review` и панель из пяти

> Last reviewed: 2026-11-10

Правила — [`docs/AGENT_RULES.md`](../../../docs/AGENT_RULES.md), раздел «3. Ревью PR». Этот навык — порядок действий.
Расходятся — прав файл правил, а навык правится в том же PR.

## 1. Подготовка

1. `git fetch origin main && git merge origin/main` в ветку PR — проверяем то, во что PR вольётся.
   Чужую ветку не перебазируем.
2. Простыми словами, 3–6 строк: что PR делает и зачем. Не пишется коротко — PR делает слишком много.
3. `pnpm check` — зелёная. В ней же сверка правил уровней (`tests/reviewTier.test.ts` зовёт `tools/review-tier.sh --self-test`).

## 2. Уровень ревью

`tools/review-tier.sh --action` — уровень по путям изменённых файлов, `--explain` — по файлам и правилам,
`--levels` — легенда уровней. Правила — `tools/review-tier.rules`. Уровень PR — наибольший из уровней его файлов.

| уровень | что меняется | что делаем | примеры |
|---|---|---|---|
| 0 | документы, справка `content/`, тесты, навыки `.claude/` (кроме исполняемых скриптов), подъём `version` | ревью нет: основная проверка | правка главы справки, строка в документе, подъём версии, новый тест |
| 1 | мелкое поведение: всё, что не 0 и не 2 | `/code-review medium --max-findings 5`. Уровень пишем явно: скилл запоминает прошлый. `max` и `ultra` запрещены | исправление в одном компоненте, текст интерфейса, новая настройка без денег и прав |
| 2 | деньги, безопасность, сборка, CI, Dockerfile и образы, публичный API (MCP, контракт 1С), схема базы | панель из пяти параллельно (п. 3); `/code-review` при панели не зовём | цена и заявка, вход и ключи доступа, Bearer MCP, `shared/onec/schemas.ts`, `server/db/`, `Dockerfile`, CI |

- **Ручной уровень** главнее автоматического. Его задаёт слово владельца («уровень 2», «панель», «без ревью»)
  или строка «Уровень ревью: N» в описании PR: тогда `tools/review-tier.sh --level N --action` (или
  `REVIEW_TIER=N`). Вывод показывает оба: «вручную N, по путям M».
- Агент вправе **поднять** уровень сам: сомнение; правка выросла из рассуждения, а не из замера; в тексте
  цена или условия лицензии. **Понизить** вправе только владелец: ручной уровень ниже автоматического
  печатает предупреждение.
- Пути с пометкой «слово владельца» меняются только по слову владельца.
- Какая модель и усилие, сколько агентов за раз — режим «экономия» или штатный, раздел «3. Ревью PR».

## 3. Панель — пять агентов одним сообщением, параллельно

| роль | модель, усилие | смотрит |
|---|---|---|
| **Документация** | Sonnet, среднее | `docs/`, `README.md`, `CLAUDE.md`, `content/help/`, `.claude/skills/` — верны ли против кода, открываются ли ссылки, запускаются ли команды |
| **Инженер** | Sonnet, среднее | верность решений, канон репозитория (чистые функции в `shared/` и `server/utils/`, JSDoc, типизация TS, только Bitrix24 UI); Dockerfile и образ: пользователь не root, базовый образ и зависимости закреплены; контракт 1С только в `shared/onec/schemas.ts` |
| **QA** | Sonnet, среднее | краснеет ли тест, если сломать код; всё ли заявленное в PR проверено; правки страниц — отрисовываются ли (`AGENT_RULES.md` §5.3а); что можно проверить только на стенде, коробке или живой 1С — так ли и названо |
| **Безопасность** | Sonnet, среднее | сессии и ключи доступа клиентов, изоляция данных между компаниями, Bearer MCP, фрейм-авторизация Б24, SSRF, ввод; ключи только в `.env`, порты только на 127.0.0.1 или во внутренней сети, supply chain, ПДн не на диске и не в логах |
| **CTO** | Sonnet, среднее | изменение целиком: объём, цена, направление, что оно обещает клиентам; выкладка, образ и теги, откат, серверы клиентов — по команде владельца; не решение ли это владельца |

Модель — параметр запуска агента. Усилие — как позволяет среда запуска; **максимум усилия — никогда**.

Каждому в задании — дословно по смыслу:

- Проект большой. Начни с `git diff origin/main...HEAD --stat`, читай по делу, не грузи всё дерево.
- Дерево общее. Чужая правка — сосед, не откатывать и не строить на ней теорий.
- Код меняет только QA и только чтобы проверить, что тест краснеет, — в отдельном `git worktree`.
  Откат мутации — из копии во временном каталоге, **никогда** `git checkout --`.
- Внешний API и ядро сверять с источником, не по памяти: Битрикс24, b24jssdk, b24ui — навык `b24-docs`.
- Ключи, вебхуки и данные клиентов в отчёте не цитировать.
- Сообщать находки: файл:строка, что, почему важно, как чинить, насколько уверен. Не чинить.

## 4. Отчёт владельцу — по-русски, коротко

Блок на проверяющего: **кто — что — почему важно — как чинить**. Без стенограмм. Отдельно — что берёшь
в работу и что нет, с причиной и замером.

## 5. Исправления и повтор

- Всё — **в этом же PR**. Просится в отдельный issue или PR — не выносить молча, сказать и обсудить.
- Исправленный гард — с тестом, который краснеет при мутации (`AGENT_RULES.md` §5.2).
- После правок: `pnpm check`, пуш. Перепроверяет **только нашедший** замечание: та же роль, один агент.
- Вся панель заново — только если PR переписан. Серия связанных PR — **одна панель на общий дифф** серии.
